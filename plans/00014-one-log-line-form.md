# 00014 — One form for a log line

> Status: **approved 2026-11-23**. Supersedes nothing.

On 2026-11-19 the maintainer asked for one logging standard across the family, in ClaudeForge's
form: "I want ClaudeForges form everywhere and we should coordinate that standard with Templates
session to route to the appropriate repo to enforce it". DiffView's session brought the request here
from its own plan 00037, a draft in which every surface logs what its user did. The maintainer chose,
through `choices` the same day, to draft this plan.

## What exists today

| Where | What it is |
|---|---|
| ClaudeForge `src` | The model, read by DiffView's session on 2026-11-19 across 353 files. Of 151 templates at Information, 67 are `[Area.Kind]` and key=value pairs only, e.g. `[Backup.Tab] index={Index} tab={Tab}`; 44 are `[Area]` and a sentence; 17 are `[Area.Kind]` with a sentence and pairs; 9 `[Area]` with both; 7 `[Area.Kind]` with PascalCase keys; 2 `[Area]` with pairs only; 5 carry no tag (`Starting`, `Exiting ClaudeForge`). Warnings are mostly `[Area]` and a sentence. Nothing writes the form down and no test holds it |
| ClaudeForge's redaction | `SensitiveKeys.IsSensitive`, in `src/AgentForge.Sdk/Diagnostics/SensitiveKeys.cs`, used by its settings editors' `FormatValueForAuditLog`, its workspace diagnostics and its JSON redactor |
| AppKit, `AppServices.EntryPoint` | Runs every app the templates generate. `EntryRun` flushes the app's log once per run, `AppMainOptions.FlushLog`, and writes no line of its own, read on 2026-11-19 |
| AppKit, `AppServices.Logging` | `BucketedRollingFileSink`, a public Serilog `ILogEventSink` writing a file per bucket, eight hours by default, kept three days; it renders `{Message:lj}` |
| AppKit's own lines | Not in the form: its Avalonia bridge, `SerilogAvaloniaSink.cs:91`, writes `[Avalonia:{Area}] {Message}`, forwarding Avalonia's own text, and `UiThreadExceptions.cs:437` and `AvaloniaDiagnostics.cs:536` write sentences with `:l` holes |
| AppKit, `AppServices.EntryPoint` and `.Abstractions` | `AppServices.EntryPoint.csproj` says "THIS PROJECT HAS NO REFERENCES, AND THAT IS THE POINT", held by its `LayeringTests`: it reaches the app's log only through the `FlushLog` callback, and an app configures its logging inside the run. `AppServices.Abstractions` references nothing either; `AppServices.Logging` references Serilog |
| How the apps are compiled | `bbapi` is native, `PublishAot`, with the AOT and trim analysers' warnings as errors on every build; `bbconsole` is trimmed, warnings as errors; `bbavalonia` is trimmed, with the compiler's warnings as errors and ILLink's held to `trim-warnings.txt`; `bbweb` is not trimmed |
| The templates | Write no log line. `bbavalonia` logs through Serilog, which `AvaloniaDiagnostics.ConfigureLogging` installs; `bbweb` and `bbapi` through ASP.NET Core's Microsoft.Extensions.Logging console, every line on stderr so stdout stays free, with levels in `appsettings*.json`'s `Logging:LogLevel`; `bbconsole` configures none and has no generic host |
| CodeQuality's reach | Pinned with warnings as errors in every template and in ClaudeForge, DiffView, AutoVersioning, FileServer, XamlQuality and AppKit. DiffView's `AGENTS.md:29` requires `:l` on every string hole, the opposite of decision 3 |
| `docs/repository-conventions.md` | Says nothing about logging |
| DiffView | Its library logs through `ILogger` only; its demo bridges Serilog into it. DiffView's session reports that its `AGENTS.md` records two measurements: MEL writes a string hole as it is, while Serilog quotes it unless the hole is `:l`; and `:l` on an enum throws `FormatException` inside the log call. After its plan 00037 was approved on 2026-11-21 it measured `{Message:lj}`, through Serilog directly and through Serilog.Extensions.Logging 10.0.0: an enum renders quoted, `level="Warning"`, because `j` formats every scalar but a string as JSON; the same enum passed as its name, a string, renders bare, `level=Warning`; booleans render `flag=true`, numbers `count=7 ratio=0.5`, and a hand-quoted string `section="…"` once. MEL's own formatter writes the enum bare and a boolean `True`, so a library test that formats through MEL sees a different line from the family's sinks |

A log line is read by a person after the fact, and by an agent grepping for one thing a user did.
ClaudeForge's pure lines serve both: one tag to grep, then fields that need no parsing of prose.

## Decisions

| # | Decision | Why |
|---|---|---|
| 1 | **Every line the family's code writes starts with a tag `[Area.Kind]`**, both parts PascalCase, one dot, nothing before it. A line a framework writes, ASP.NET Core's, passes through as it is. Text the family's code forwards, Avalonia's through AppServices' bridge, is a value of a line in the form, e.g. `[Avalonia.Log] area={Area} text="{Message}"`. `Area` is the surface or subsystem (`Backup`, `Diff`, `App`); `Kind` is what happened there (`Tab`, `Open`, `Start`). `[Area]` alone is not allowed (the maintainer, 2026-11-20, through `choices`) | One shape to grep: `[Backup.` finds an area, `[Backup.Tab]` one event. An `[Area]`-only line is the form that drifts into a sentence: 53 of ClaudeForge's 55 `[Area]` lines at Information carry one |
| 2 | **After the tag, key=value pairs only, separated by single spaces; no sentence.** Keys are camelCase (`index`, `tab`, `elapsedMs`). A Warning or Error says why in a pair, `reason=…`, and the exception goes in the call's exception argument, never in the template (the maintainer, 2026-11-20, through `choices`) | Pairs are what make a line machine-readable without a parser per message. camelCase is what ClaudeForge's 67 model lines use; 7 PascalCase lines are the minority |
| 2a | **Every app the templates generate logs through Serilog**, plugged into Microsoft.Extensions.Logging by Serilog's own bridge: `bbweb` and `bbapi` through Serilog.Extensions.Hosting, or Serilog.AspNetCore where it builds clean under the app's analysers; `bbconsole`, which has no host, through Serilog itself; `bbavalonia` through AppServices as today. `bbweb` and `bbapi` keep writing to the console, now Serilog's, every line on stderr as today, their levels set in code in place of `appsettings*.json`'s `Logging:LogLevel`; `bbconsole` writes AppServices.Logging's `BucketedRollingFileSink` only, so its standard output stays the tool's own (the maintainer, 2026-11-20, through `choices`). A library, `bbpkg`'s, logs through `ILogger` only and leaves the sink to the app (the maintainer, 2026-11-20, through `choices`) | One renderer for every app, so a template prints the same line in every app of the family, and code written against `ILogger`, DiffView's library among it, is rendered by the same Serilog sinks as the app's own lines |
| 3 | **A value is quoted when it is free text** (a name, a path, a heading, a reason): written with its quotes in the template, `name="{Name}"`. Numbers, booleans, enums and identifiers are written bare: `index={Index}`, `flag={Flag}`, `mode={Mode}`. An enum is passed as its name, a `string` (`mode.ToString()`), never as the enum, because the sinks would quote it. No hole carries `:l`. Every sink the family's apps write to renders the message as `{Message:lj}`: in the templates a test holds it (step 2), elsewhere review does. A sink, formatter or test helper that renders through `LogEvent.RenderMessage()` or a rendered-JSON formatter quotes strings itself and is not used. A quote inside a quoted value is not escaped (the maintainer, 2026-11-20, through `choices`) | Under `{Message:lj}` Serilog writes a string as it is, so the hand-written quotes are the only ones, as in ClaudeForge's 67 model lines. Every other scalar it writes as JSON, so an enum would print `level="Warning"`; its name, a string, prints `level=Warning` there and under MEL's own formatter alike (DiffView's measurement, above); AppServices' rolling file and ClaudeForge's live log window render `{Message:lj}` today. `:l` in a template does nothing under such a sink, and on an enum fails: DiffView measured a `FormatException`, and under a Serilog sink the line may instead be dropped. Step 1 measures what an app sees, and each sink, before the text is written; escaping inside a value is left until a line needs it |
| 4 | **One Information line per thing a user did, and nothing continuous.** No pointer motion, no scrolling, no keystroke as typed, no timer tick at Information; a run's internals log at Debug. A thing that happens in bursts logs its outcome once, `count=`. `bbweb` and `bbapi` set Serilog's level for `Microsoft.AspNetCore` to Warning, leaving `Microsoft.Hosting.Lifetime`'s start-up lines at Information (the maintainer, 2026-11-20, through `choices`) | The balance the maintainer values in ClaudeForge's log: it reads as a list of what the user did. No analyzer can tell an action from a tick, so this is prose in the conventions and a review question |
| 5 | **Every run writes a start line and an exit line, from the entry point**: `[App.Start] app=… version=… pid=…` once the app's logging is set up, and `[App.Exit] code=… elapsedMs=…` before its log is flushed and before a host disposes it. A log with a start line and no exit line reads as a death. `AppServices.EntryPoint` writes both through a callback the app passes in `AppMainOptions`, a new member beside `FlushLog`, so it keeps referencing nothing and every app the templates generate has them without writing them (the maintainer, 2026-11-20 and 2026-11-21, through `choices`) | `EntryRun` already owns the one place every run passes through on the way in and on the way out, and already reaches the log by a callback, `FlushLog`. A logger cannot exist before the app's own code sets it up, and `bbweb` and `bbapi` dispose their host, and its log, before `FlushLog` runs, so the exit line has to be written earlier than the flush |
| 6 | **Never in a value**: a secret, a token, a password, an environment variable's value, document or clipboard text, a search query (log its length, `queryLength=`). A value under a sensitive key goes through one helper in `AppServices.Abstractions`, which references nothing, modelled on ClaudeForge's `SensitiveKeys`, which writes `***`. No analyzer holds it; review does (the maintainer, 2026-11-20 and 2026-11-21, through `choices`) | A log is attached to issues and read by agents; what is in it is published in effect. One helper with one list of sensitive key names is what keeps the list from being redrawn at every call site. In a package that references nothing, a library logging through `ILogger` only can use it without taking Serilog |
| 7 | **The text lives in `docs/repository-conventions.md`, as *Log lines*; the grammar is enforced by a CodeQuality rule; the start and exit lines by AppServices.EntryPoint.** The rule, a new BNCQ id, reads the constant template of every `ILogger.Log*`, `LoggerMessage` and Serilog `Log.*`/`ILogger.*` call and reports a template not of the form of decisions 1 to 3, any hole carrying `:l`, and an enum-typed argument to a hole. It does not judge decision 4 or 6. It is on by default, at warning, so with warnings as errors a repository whose lines are not yet in the form cannot take the CodeQuality release that brings it until it converts them or suppresses the rule (the maintainer, 2026-11-20 and 2026-11-21, through `choices`) | The conventions are prescribed in this repository and enforced where each check can see: `repo-conventions check` reads files, not syntax, so it cannot see a log call; CodeQuality already reaches every family repository and every template, through the package and BNCQ's warnings-as-errors. The entry point is AppKit's |
| 8 | **The rule, and the start and exit lines with the redaction helper, are planned and released by their owners**, Inspections and AppKit, each by a plan of its own that cites this one. Templates' part is the text, the move to Serilog of decision 2a, and the templates' pins once those releases are out. AppKit's own lines, its Avalonia bridge's tag among them, come into the form in AppKit's plan, before the rule reaches AppKit's build. Every other repository that pins CodeQuality, ClaudeForge, DiffView, AutoVersioning, FileServer and XamlQuality, converts its own lines, or suppresses the rule, at the upgrade that brings it; DiffView's `AGENTS.md` drops its `:l` requirement then. Each is told when the rule's release is out | As every family convention whose enforcement lives in a package has reached the family: CodeQuality's rules and AppServices' entry point change in their own repositories, on their own releases |

### Dismissed

- **Allow `[Area]` and a sentence beside the pure form.** It is ClaudeForge's most common form after
  the pure one, and the form that does not grep or parse. Every line being one shape is what makes a
  rule possible at all.
- **Structured logging only: no tag, the event name as a property.** It reads well in a structured
  sink and badly in the plain text file and console that the family actually reads.
- **Enforce it in `repo-conventions check`, by matching text.** A regex over source cannot tell a log
  call from a string that looks like one, nor a string hole from an enum hole.
- **Let Serilog quote: sinks render `{Message}`, templates write `name={Name}`.** Serilog would quote
  and escape every string, ids too, AppServices' sinks would change, and a hand-quoted line would print
  its quotes twice.
- **Keep Microsoft.Extensions.Logging's console in `bbweb` and `bbapi`.** It writes a string as it is
  and ignores the sink's template, so the same line would print differently in a web app and a desktop
  app.

## Scope

**In:** step 1's measurement, which adds Serilog and Serilog.Extensions.Logging to `Templates.Tests` as
test dependencies; decision 2a's move of `bbweb`, `bbapi` and `bbconsole` to Serilog, with
`verify-release`'s required list and tests for it; the *Log lines* section of `docs/repository-conventions.md`; one line
pointing to it in each template's root `AGENTS.md`, under *Every change*; a message to Inspections and
to AppKit with the approved text, and to DiffView with the rule's id once Inspections gives one; the
templates' pins of CodeQuality and AppServices once those releases are out; `PROGRESS.md`.

**Out:** writing the CodeQuality rule and the entry point's lines, which their owners plan; bringing any
repository's existing lines into the form, which each does when the rule reaches it; ClaudeForge,
which is not ours to sync; level switches and retention beyond what step 2's setup needs.
